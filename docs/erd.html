GodLife ERD 설계도 · 1~3차 전체 · 초안 v0.1

갓생살기의 전체 기능 명세(계정 · 챌린지 · 인증 · 원장/정산 · 랭킹 · AI 검증 · 부정행위 방지 · 소셜 · 결제 · 마켓플레이스)를 38개 테이블로 옮긴 논리 ERD. 표에 마우스를 올리면 연결된 표만 강조됩니다.

설계 메모

잔액은 원장이 진실

point_transactions 는 INSERT-only 이고 잔액은 항상 SUM(amount). wallets.balance 는 조회 성능용 캐시이자 SELECT … FOR UPDATE 를 거는 락 앵커.

이중 지급을 스키마가 막는다

point_transactions.idempotency_key · payments.order_id · orders.request_key · settlements.challenge_id 가 모두 UNIQUE. 재시도나 배치 재실행이 와도 두 번째 INSERT 는 제약 위반으로 실패한다.

정산 추적성

settlement_items 가 지급 원장(refund_tx_id / reward_tx_id)을 직접 가리켜, “누가 왜 얼마를 받았는지”를 정산 → 원장 순으로 따라갈 수 있다.

현금화 경로 없음

출금·환전·계좌 관련 테이블을 일부러 두지 않았다. 충전(CHARGE)과 소비(ENTRY_FEE · PURCHASE)만 존재하는 폐쇄형 경제 — 도박이 아니라는 설계 근거.

개인정보

비밀번호 BCrypt, 휴대폰 번호는 HMAC 해시(UNIQUE 로 1계정 제한)만 저장, 배송지 전화번호는 AES 암호화, 카드정보는 컬럼 자체가 없음(PG 토큰만).

AI 검증 데이터

ai_inference_results 는 모델 버전과 함께 판정을 보존해 재현 가능하고, image_embeddings 는 코사인 유사도 비교용 벡터. 애매한 건은 review_queue 로 넘어간다.

확인이 필요한 가정

  • 참가비: challenges.entry_fee(개설자 지정)와 min_bet/max_bet(허용 범위)을 모두 두고 CHECK 로 묶었습니다. 참가 시점 금액은 challenge_participants.deposit_amount 에 스냅샷.
  • 몰수(FORFEIT)는 지갑 잔액이 변하지 않으므로 원장 타입이 아니라 settlement_items.forfeit_amount 로 기록합니다 (참가 시 ENTRY_FEE 로 이미 차감됨).
  • 일일/월간 베팅 상한 사용량은 별도 테이블 없이 원장에서 실시간 집계합니다. 트래픽이 커지면 캐시 테이블을 추가할 수 있습니다.
  • 주간 리포트의 코칭 문구(weekly_reports.coaching_text)는 생성 방식이 미정이라 컬럼만 잡았습니다. 인증 검증과 달리 과제 필수 요건 대상은 아닙니다.
